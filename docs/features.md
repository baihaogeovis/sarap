# SARAP 功能说明

SARAP 是一套可复用的多场景 SAR 应用平台。第一版同时交付两件事：平台骨架，以及挂在平台上的洪水应急场景。洪水是一个已注册场景，不是单独的洪水系统。

仓库地址：[https://github.com/baihaogeovis/sarap](https://github.com/baihaogeovis/sarap)

## 第一版范围

平台骨架包括：登录与三角色（管理员、值班员、只读）、组织/项目/区域、数据编目与版本化本底库、场景开通、任务中心、产品库、简单质检与发布、一张图、应急简报。权限模型按完整版设计，第一版界面先精简。

洪水场景使用 Sentinel-1 IW GRD 和 SNAP，产出淹没准范围、面积统计和应急专题图。起算点是数据已经在平台就绪；对外建议在 4 小时内出范围和面积（`suggested_target_minutes=240`），这是建议目标，不是合同 SLA。第一版不承诺精细水深，也不在引擎里下载 Sentinel-1。

试点区、分析坐标系 `analysis_crs` 按项目配置，不在代码里写死某条流域。演示数据里的 `demo-pilot` 只是占位 AOI（地理 `EPSG:4490`，分析 `EPSG:4548`，算法配置档 `s1_grd_flood_v1`）。

## 角色

| 角色 | 能做的事 | 不能做的事 |
|------|----------|------------|
| 管理员 `admin` | 管组织、项目、成员、场景；建任务；质检、发布和撤回产品；发布简报 | — |
| 值班员 `duty_officer` | 建任务、起草产品、提交质检、做质检并发布产品、起草简报。产品发布后即可看默认简报 | 管成员、开通/配置场景、撤回已发布产品。种子权限里没有 `briefing.publish`，简报记录的发布由管理员做 |
| 只读 `readonly` | 看已发布产品和简报、默认一张图、任务列表 | 任何写入 |

数据模型里已经预留了 `platform_admin`、`org_admin`、`project_admin`、`qc_reviewer`、`analyst` 以及独立的 `SERVICE` 服务账号类型，第一版登录界面暂不开放。

## 界面模块

导航为：**工作台 / 任务 / 一张图 / 简报 / 资源 / 管理**。视觉为深海蓝作业台（画布 `#0F1A22`，主色 `#0E4D6B`，强调 `#C45C26`，水域 `#2A6F7A`）。

- **工作台**：一键建任务，沿找数 → 处理 → 质检 → 发布的主路径作业。
- **任务**：任务列表与详情，查看处理状态和产物。
- **一张图**：选择项目里的区域后，叠加该区域已发布产品的淹没或水体范围，以及该产品算出的道路、居民点、行政区（OpenLayers 读取平台回传的 GeoJSON）。右侧给出淹没或提取水体面积，以及受影响道路长度、居民点个数和面积、行政区个数和面积。默认图只含 `published`。没有已发布产品时显示空状态，不编造淹没面，也不编造影响数字。支持图层开关、点选识别和 PNG 导出。分析仍用区域自己的 `analysis_crs`（10 m），地图只做展示用的经纬度。
- **简报**：默认简报按所选区域最新的已发布产品生成，带应急图图层、面积和影响统计、结论和限制说明。草稿、待质检、已撤回的产品不进入这张图。可以把当前视图存成简报草稿；把简报记录标成已发布需要 `briefing.publish`。
- **资源**：编目与本底等数据资产。
- **管理**：项目、区域、成员、场景开通。

## 洪水产品口径（摘要）

正式「本次淹没」= 当期确定水体 − 有效且已发布的常年/季节本底。本底缺测处不得算成洪水。没有已发布常年水体本底时，只可出当期水体（类别 5 / 提取水体），并标记 `flood_event_status=baseline_missing`，不得把当期水体改名为「本次淹没」，也不得自动发布本次淹没产品。第一版对外统计以面积为主，不提供水深产品。分析在试点 `analysis_crs` 的 10 m 网格上进行，不得用 Web Mercator 做分析原数据。

## 当前落地情况

本地骨架已经搭齐：

- 平台 API（`apps/api`）：FastAPI。`GET /products/map` 和 `GET /briefings/preview` 只使用所选区域的已发布产品，并把矢量从该区域的 `analysis_crs` 转到 `EPSG:4326`。交叉统计写在 `impact_stats`，没有配置对象时不补空行。
- 前端作业台（`apps/web`）：Vite + React + TypeScript + OpenLayers 10。值班员可以选区域、已入仓影像和已发布本底，创建洪水任务。一张图和简报按所选区域显示已发布范围、影响对象和统计。
- 处理引擎（`engine`）：独立包，带 `Dockerfile`。mock 通路可跑通，并由后台 worker 消费队列。mock 会把合成窗口放到区域 AOI 的分析网格上。演示区域把影响对象指到仓内小夹具 `fixture:public_validation_window`（800 m 窗口，西侧开阔水体，坐标是相对窗口西北角的米，不是国内标注场景，也不含 Sen1Floods11 栅格）。叠加在分析坐标系的 10 m 网格上完成，再把 GeoJSON 随内部入库接口回传。SNAP 模式若找不到 `gpt`，以 `GPT_NOT_FOUND` 失败，不会偷偷改走 mock。专题图目前是 PNG 预览加 JSON 说明，不是 GeoPDF。

更细的模块划分见 [架构说明](architecture.md)，待办见 [TODO](TODO.md)，本地与部署步骤见 [部署说明](deployment.md)。

## 第一版明确不做

- 精细水深或水深分级产品。
- 引擎侧检索和下载 Sentinel-1。
- 第一版并行再起一套 Java / Spring 后端（数据模型已按可被后续网关对接来设计）。
- 需求里列为 P1 的通知、多期对比、自动入库，不作为第一版必做。
